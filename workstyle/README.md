# 스틸 워크 스타일 (STEEL WORK STYLE)

> 업무 스타일 진단 — **기획과 구성 by 곤사마**

직장인이 자기 업무 방식을 스스로 점검하고, 함께 일하는 사람과의 궁합을 확인하는 웹앱.
팀 워크숍과 신입 온보딩에서 쓰는 것을 전제로 만들었다.
철강 일본어 학습 앱 **스틸링고**와 같은 계열이며, 마스코트와 색 팔레트를 공유한다.

## 파일

| 파일 | 내용 |
|---|---|
| `index.html` | 앱 본체. 브라우저로 열면 바로 실행된다. |
| `manifest.json`, `sw.js`, `icon*` | 설치(PWA)와 오프라인 실행에 쓰는 것들. |
| `src/문항설계_v2.html` | 문항 전문과 축별 이론 근거를 정리한 설계 문서. v2에서 뺀 문항도 이유와 함께 표시해 두었다. |

서버는 없어도 된다. `index.html` 하나에 앱 전부가 들어 있고,
답과 결과는 어디에도 저장·전송되지 않는다.

## 설치해서 쓰기

표지 화면 아래 **기기에 설치해서 쓰기**에 두 가지 길을 뒀다. 어느 쪽이든 인터넷 없이 열린다.

**① 앱으로 설치 (PWA)** — 웹 주소로 열었을 때 쓴다.
홈 화면·시작 메뉴에 아이콘이 생기고 주소창 없는 창으로 뜬다.
서비스 워커가 파일을 받아두므로 망이 끊겨도 그대로 동작한다.

- 안드로이드·PC 크롬/엣지 — 표지의 `앱으로 설치` 버튼, 또는 주소창의 설치 아이콘
- 아이폰·아이패드 — 사파리 **공유 → 홈 화면에 추가**
- 설치를 띄우려면 `https`로 서비스해야 한다. 이 저장소에 Pages가 켜져 있으면
  `https://savvygonsama.github.io/my-web-apps/workstyle/` 로 열었을 때 조건이 맞는다.

**② HTML 파일로 저장** — 파일을 직접 열어 본 경우를 포함해 어디서든 된다.
지금 보고 있는 화면을 파일 하나로 떨궈준다. 받은 파일을 더블클릭하면 끝이고,
사내 메신저나 공유 폴더로 그대로 돌려도 된다. 망을 안 타는 게 확실해야 하는 현장에는 이쪽이 편하다.

## 결과를 어떻게 보여주는가

설명만 늘어놓으면 사람들은 "그런가 보다" 하고 창을 닫는다. 그래서 축마다
**사무실에서 실제로 벌어지는 장면**을 하나씩 붙였다. 카드 하나가 세 칸으로 되어 있다.

| 칸 | 내용 |
|---|---|
| **장면** | 대사가 있는 상황. 예 — 사고가 난 순간 과업 중심인 사람의 첫마디가 "그래서 원인이 뭐예요?"로 나가고, 그 팀원은 그날 저녁 "혼났다"고 말한다. |
| **상대 속마음** | 그 자리에 있던 사람이 속으로 한 말. 판단이 아니라 사정이다. |
| **그래서 이렇게** | 다음 주 월요일에 바로 할 수 있는 것 하나. "앞에 여섯 글자만 붙이세요 — 많이 놀랐죠?" |

축 여덟 개 × 양쪽 끝 = **장면 16개**, 여기에 균형일 때의 장면이 하나 더 붙는다.
직책자와 팀원은 같은 축이라도 겪는 장면이 달라서, 필요한 곳은 자리에 맞는 판으로 갈아끼운다.

궁합 화면에도 같은 방식으로 **두 사람 사이의 장면**을 넣었다.
같은 장면을 놓고 "나는 이래서 그랬다"와 "저 사람은 이래서 그랬다"를 나란히 보여준다.

## 구조

**8축 32문항** (약 5분)

| 축 | 양쪽 끝 | 바탕이 된 연구 |
|---|---|---|
| 추진 템포 | 속도형 ↔ 완성도형 | 성실성(Big Five)의 신중성 요인 |
| 우선순위 | 과업 중심 ↔ 관계 중심 | 오하이오 리더십 2요인 |
| 의사결정 | 주도형 ↔ 조율형 | 주장성 연구, 참여적 의사결정 모형 |
| 시야 | 큰그림형 ↔ 디테일형 | 해석수준이론 |
| 변화 대응 | 검증 후 이동 ↔ 일단 시도 | 조절초점이론 |
| 피드백 방식 | 직설형 ↔ 완곡형 | 공손성 이론, 피드백 개입 메타분석 |
| 일 맡기고 받기 | 자율 선호 ↔ 절차 선호 | 자기결정이론, 직무특성모형 |
| 압박 상황 | 정면 돌파 ↔ 거리 두고 재정비 | 스트레스 대처 이론 |

앞의 네 축은 일하는 방식, 뒤의 네 축은 사람 사이에서 마찰이 생기는 지점이다.

**역할 분기** — 첫 화면에서 직책자와 팀원 중 하나를 고르면 문항 7개의 장면이 바뀐다.
팀원에게 성립하지 않는 상황("팀원이 실수했다", "일을 맡길 때")을 갈아끼우기 위한 것이고,
**축·방향·채점 방식은 양쪽이 완전히 동일하다.** 이게 지켜져야 두 사람을 같은 자로 잴 수 있다.

**결과** — 여덟 축 기울기 그래프, 강점·주의 카드, 약점별 실천 팁, 어울리는 일과 힘이 더 드는 일,
그리고 결과 코드.

**궁합** — 각자 진단을 마친 뒤 결과 코드를 주고받는다. 상대 코드와 관계(상사/동료/후배)를 넣으면
반대로 기운 축의 마찰과 대처법, 같은 쪽으로 기운 축의 공유 맹점을 보여준다.
같은 조합이라도 상대가 상사냐 후배냐에 따라 조언이 달라진다.

## 결과를 다루는 기능

| 기능 | 하는 일 |
|---|---|
| **이 기기에 저장** | 결과를 브라우저 안에 최대 10건까지 남긴다. 다음에 열면 표지에 목록이 뜨고, 다시 풀지 않아도 결과 화면이 그대로 열린다. |
| **결과 공유하기** | 요약과 결과 코드를 문장으로 만들어 보낸다. 모바일은 시스템 공유창(카톡·메일 등), 데스크톱은 클립보드 복사로 넘어간다. |
| **코드만 복사** | 결과 코드만 복사한다. |
| **인쇄 · PDF 저장** | 워크숍에서 종이로 돌릴 때 쓴다. |
| **1:1 궁합** | 상대 코드 + 관계(상사/동료/후배)를 넣으면 마찰 지점과 대처법이 나온다. |
| **팀 지도** | 이름과 코드를 12명까지 모아 팀 전체를 한 장으로 본다. |

저장은 전부 **이 브라우저 안에서만** 끝난다. 서버가 없으니 보낼 데도 없다.
사파리 사생활 보호 모드처럼 저장 자체가 막힌 환경에서도 진단은 그대로 굴러가고,
저장만 조용히 실패하며 안내가 뜬다.

### 팀 지도

1:1 궁합이 두 사람 사이의 이야기라면, 팀에서는 다른 게 보인다.

- **팀이 함께 못 보는 것** — 기운 사람이 전부 같은 쪽인 축. 아무도 반대편을 안 보고 있다는 뜻이라 사고가 그쪽에서 난다.
- **회의가 길어지는 자리** — 양쪽으로 갈라진 축. 누가 어느 편인지 이름까지 나온다.
- **여덟 축 위의 팀** — 각 축 위에 사람을 얹은 지도. 나는 주황색이고, 같은 자리에 여럿이면 층을 나눠 쌓아서 한 명도 가려지지 않는다.

배치나 평가에 쓰라고 만든 화면이 아니다. 워크숍에서 **화면에 띄워놓고 같이 보라고** 만들었다.

## 결과 코드

```
SW-L-AAAW-AAAA
   │ └──┬───┘
   │    └── 여덟 축 점수 (-10~+10을 21단계 문자로. 헷갈리는 I·O는 제외)
   └─────── 자리: L=직책자, T=팀원
```

축마다 원점수(-8~+8)를 **-10~+10 척도로 환산**해서 넣는다.
문항 수가 달라져도 같은 자로 재기 위한 것이고, 덕분에 40문항 시절에 발급된
`SL-`로 시작하는 코드도 궁합 입력란에 그대로 넣을 수 있다.

## 설계 원칙

세 가지를 지켰다. 이걸 어기면 조직에서 못 쓰는 도구가 된다.

**1. 검사가 아니라 대화 도구다.** "당신은 ○○형"이라고 단정하지 않고 축마다 기울기를 보여준다.
성격 특성은 실제로 연속 분포이지 유형으로 딱 갈리지 않는다.

**2. 궁합은 판정이 아니라 처방이다.** "안 맞음" 대신 "이렇게 하면 통함"으로 쓴다.
닮은 조합도 "잘 맞음"으로 끝내지 않고 둘이 함께 놓칠 맹점을 반드시 같이 알려준다.

**3. 인사 평가에 쓰지 않는다.** 이 문항들은 학술적으로 타당화된 검사가 아니다.
위 이론들은 문항과 조언을 만드는 근거일 뿐이며, 앱 안에도 이 사실과 함께
채용·평가·배치의 근거로 쓰지 말라는 안내를 넣었다.

MBTI를 근거로 쓰지 않은 이유는 재검사 신뢰도가 낮고 사람을 이분법으로 나누기 때문이다.
뇌과학은 이 영역에서 실증적으로 말해줄 수 있는 게 거의 없어 근거에서 제외했다.

## 바뀐 것

**v3** — 결과를 **에피소드 형식**으로 다시 썼다(장면 → 상대 속마음 → 그래서 이렇게).
결과 저장, 공유하기, 팀 지도를 새로 넣었다.

**v2** — 이름을 맞추고, 40문항을 32문항으로 줄였다.
축은 여덟 개 그대로 두고 축마다 하나씩, **같은 것을 두 번 묻는 문항**부터 뺐다.
뒤로 갈수록 대충 고르게 되는 응답 피로를 줄이려는 것이고,
역할 분기 문항 일곱 개는 하나도 빼지 않았다. 설치와 오프라인 실행을 새로 넣었다.

## 마스코트

코일 캐릭터는 같은 팀에서 쓰는 철강 일본어 학습 앱 "스틸링고"의 것을 가져왔고,
표정 세 가지(표지·진행 중·결과)로 늘렸다. 색도 같은 팔레트를 쓴다.
앱 아이콘도 같은 코일을 정면에서 본 모습이다.
