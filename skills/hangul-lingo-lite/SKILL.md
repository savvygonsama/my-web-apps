# ハングリンゴ Lite 회차 만들기

곤사마(@POSCO)가 만든 **스틸링고 Lite의 뒤집은 판**이다. 엔진과 화면 구조는 그대로 가져왔고,
언어의 방향만 반대다. 그래서 헷갈리기 쉽다 — 아래 표를 먼저 머리에 넣어라.

| | 스틸링고 Lite | **ハングリンゴ Lite** |
|---|---|---|
| 배우는 사람 | 한국인 | **일본인** |
| 배우는 말 | 일본어 | **한국어** |
| 화면의 설명글 | 한국어 | **일본어** |
| 읽기 보조 | 한자 위 후리가나 | **한글 위 가타카나** |
| 데이터 필드 | `jp`(일본어) / `ko`(한국어 뜻) | **`ko`(한국어) / `ja`(일본어 뜻)** |
| parts 이어 붙이기 | 그냥 붙임 | **띄어쓰기 한 칸으로 이음** |
| 음성 | VOICEVOX mp3 + 브라우저 | **브라우저 한국어 음성만** |

| | 내용 |
|---|---|
| 파일 | `hangul-lingo/lite/index.html` (앱 안에 회차가 박혀 있다) |
| 현재 | 5회차 |
| 명세 | `references/schema.md` |
| 문체 | `references/style.md` |
| 검증 | `node scripts/check_day.js 파일` |
| 심사 | `references/review-panel.md` — 5인 페르소나 3라운드, 평균 9.8점 이상 |

## 작업 순서

1. **명세를 읽는다** — `references/schema.md`. 여기 요약만 보고 쓰면 반드시 어긋난다.
2. **소재 정하기** — 사용자에게 묻거나 제안한다. 짧은 생활 뉴스 한 편으로 소화되는 소재
   (날씨·재해, 교통, 가게, 계절 행사, 식당 등).
3. **원고 쓰기** — 문체와 난이도 기준은 `references/style.md`를 읽고 따른다.
4. **검증** — `node scripts/check_day.js day6.js`를 돌린다. 통과할 때까지 고친다. 건너뛰지 않는다.
5. **심사** — `references/review-panel.md`의 5인 페르소나로 3라운드 평가한다.
   평균 9.8점 미만이면 지적받은 곳을 고치고 다시 심사한다.
6. **전달** — 완성된 회차 객체를 `.js` 파일로 저장해 보내거나, 앱에 직접 넣는다(아래).

## 표기 규칙

화면에 그릴 때와 음성으로 읽을 때 쓰는 표기가 세 가지다. 이걸 틀리면 루비가 깨진다.

| 쓰는 법 | 화면 | 음성 엔진에 넘기는 것 | 쓰는 곳 |
|---|---|---|---|
| `비[ピ]` | 비 위에 ピ 루비 | `비` (한글 그대로) | 모든 한국어 |
| `{100원}[백 원/ペグォン]` | 100원 위에 ペグォン | `백 원` | 숫자·값·호선·월·시각 |
| `《비[ピ]》` | 노란 형광펜 | 표시 없이 읽음 | 그 회차 단어가 문장에 나올 때 |

- **한글 덩어리에만 대괄호를 붙인다.** 대괄호 안은 가타카나만 들어간다.
  `비[ピ]가`처럼 조사는 밖에 두어도 되고, `비가[ピガ]`처럼 통째로 묶어도 된다 —
  다만 **한 회차 안에서는 한 가지 방식으로 통일한다.** 지금 앱은 낱말과 조사를 따로 묶는다.
- **숫자는 반드시 `{}[한글읽기/カナ]`로 적어라.** 음성 엔진은 「3시」를 「삼시」로,
  「2호선」을 엉뚱하게 읽는다. 슬래시 앞은 엔진에 넘길 한글, 뒤는 화면에 띄울 가타카나다.
- 가타카나는 **문자 그대로가 아니라 실제로 들리는 소리**를 적는다.
  `왔습니다` → `ワッスムニダ`(×ワッスプニダ), `많이` → `マニ`, `같이` → `カチ`, `작년` → `チャンニョン`.
  연음·비음화·경음화를 적용한 뒤에 옮긴다. 이 앱에서 가장 자주 나는 실수다.
- 일본어 문장 안에서 인용할 때는 `"..."` 대신 「」를 쓴다. 따옴표 이스케이프 사고를 막는다.
- 강조는 `<b>...</b>`. 그 외 태그는 쓰지 않는다.

## 가타카나의 한계를 숨기지 않는다

한국어에는 가타카나로 적을 수 없는 소리가 있다. ㅓ와 ㅗ, ㄱ/ㅋ/ㄲ, 받침소리가 그렇다.
앱 머리말이 이 사실을 먼저 밝히고 있으니, 설명글에서도 **얼버무리지 말고 짚어 준다.**
낱말 하나하나의 읽기를 붙여 놓았으므로 이어 읽으면 소리가 달라진다는 점도 같이 알려 준다
(`한국` + `에서는` → 실제로는 ハングゲソヌン). 진짜 소리는 `parts[].r`의 「読み」 칸과 🔊가 맡는다.

## 검증

회차 객체 하나만 담은 파일로 저장한 뒤:

```bash
node scripts/check_day.js day6.js
node scripts/check_day.js ../../hangul-lingo/lite/index.html   # 앱 전체
```

문법 오류, 대괄호·《》 짝, 가타카나 섞임, `{}[]`의 슬래시, 필드 대응, `parts` 결합 일치,
개수 규칙, 퀴즈 정답 범위와 쏠림, 보기 길이를 본다. 사람 눈으로는 잘 안 잡히는 것들이다.
스크립트가 못 잡는 것 — 번역이 맞는지, 가타카나가 실제 소리와 맞는지, 설명이 초보자에게
통하는지 — 은 심사 단계에서 잡는다.

## 음성에 대해

이 앱에는 미리 뽑아 둔 mp3가 없다. **브라우저에 깔린 한국어 음성**을 그대로 쓴다.
그래서 회차를 아무리 추가해도 소리는 난다 — 다만 기기에 한국어 음성이 없으면
안내 창이 뜬다(윈도우·아이폰·안드로이드별 설치 방법이 앱 안에 적혀 있다).
나중에 원어민 녹음을 넣고 싶으면 `AUDIO_DATA`에 `{해시: 데이터URL}` 꼴로 심으면 된다.
해시 계산법은 `references/schema.md` 맨 아래에 있다.

## 앱에 넣기

아티팩트가 아니라 **저장소 안의 파일**이다. 회차를 넣는 자리는 `hangul-lingo/lite/index.html`의
`const DATA = [ ... ];` 배열 맨 끝, 마지막 회차 객체 뒤에 쉼표를 찍고 이어 붙이는 것이다.
넣은 뒤 반드시 `check_day.js`를 앱 파일에 대고 한 번 더 돌린다.

회차를 늘렸으면 `sw.js`의 `CACHE` 버전(`hangul-lingo-lite-v1`)을 한 칸 올려 준다.
안 올리면 이미 설치한 사람에게 새 회차가 늦게 도착한다.

## 사용자에 대해

사용자는 본인을 "컴맹"이라고 말한다. 기술 용어를 앞세우지 말고, 무엇을 왜 하는지 짧은 문장으로
설명하고, 파일을 어디에 어떻게 넣는지는 단계별로 안내한다. 결과물은 항상 파일로 만들어 보낸다.
