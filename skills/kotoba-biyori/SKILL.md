# ことば日和 회차 만들기

곤사마(@POSCO)가 만든 일본어 학습 웹앱이다. 현재 **30일차**까지 있고, N3 수준이다.

스틸링고와 결정적으로 다른 점이 하나 있다. **후리가나를 직접 달지 않는다.**
앱이 `FDICT`라는 사전을 들고 있다가 화면에 그릴 때 자동으로 붙인다.
그래서 원고에는 `気になる`라고만 쓰면 되고, 대신 **읽기가 표기와 맞물리는지**가 중요해진다.
맞물리지 않으면 그 말에는 후리가나가 안 붙는다. 검증기가 이걸 잡는다.

하루치의 짜임은 이렇다.

```
주제 하나 (예: 마음을 말하는 말)
  → 단어 10개, 각각 예문 2~3개와 설명
  → 뿌리 한자 하나에서 뻗어 나온 말들 (예: 気 → 気を使う·気が済む·気に入る…)
  → 퀴즈 6문항
  → 문화 칼럼 (일본어와 한국어가 닮았는데 어긋나는 지점)
```

## 작업 순서

1. **주제 정하기** — 사용자에게 묻거나 제안한다. 주제는 **뿌리 한자 하나로 묶이는 말들**이면 가장 좋다.
   気(마음), 手(손·솜씨), 目(눈·시선), 口(입·말), 気持ち 계열처럼.
   기존 30일차와 겹치지 않게, 사용자에게 지금까지 다룬 주제를 확인하고 시작한다.
2. **원고 쓰기** — `references/schema.md`를 읽고 그 형식대로 쓴다. 문체 기준은 `references/style.md`.
3. **검증** — `node scripts/check_day.js day31.js`. 통과할 때까지 고친다.
4. **후리가나 확인** — 아래 "후리가나" 항목대로 사전에 없는 한자를 찾아낸다. 이 단계를 빠뜨리면
   앱에서 한자가 맨몸으로 나온다.
5. **전달** — 완성된 객체를 `.js` 파일로 저장해 사용자에게 보낸다.

## 후리가나 — 이 앱에서 가장 조심할 것

앱은 `FDICT`(표기 → 읽기 사전)를 최장일치로 훑어 후리가나를 붙인다.
사전에 없는 한자는 `<span class="nofuri">`로 감싸져 **후리가나 없이** 나온다.

그래서 새 회차를 쓰면 두 가지를 해야 한다.

**하나 — 표기와 읽기가 맞물리는지 확인한다.**
`ja: "落ち着く"`, `kana: "おちつく"`처럼 오쿠리가나가 서로 맞물려야 앱이 落=お, 着=つ로 쪼갤 수 있다.
어긋나면 후리가나가 통째로 안 붙는다. 검증기가 앱과 똑같은 방식으로 확인한다.

**둘 — 새로 등장한 한자를 FDICT에 넣는다.**
앱에 감사 기능이 들어 있다. 회차를 넣은 뒤 브라우저 개발자 콘솔에서 `kbAudit()`를 실행하면
사전이 덮지 못한 한자를 전부 찾아 준다. 나온 한자를 `FDICT`에 추가하면 된다.

```js
const FDICT = {
  "気": "き", "人": "ひと", ...
  "새한자": "읽기",           // 여기에 추가
  "새로운말": "あたらしいよみ"   // 낱말 단위로 넣으면 최장일치로 더 정확해진다
};
```

낱말 단위 항목이 낱자 항목보다 우선한다. 「気が付く」처럼 읽기가 특별한 말은
낱말 통째로 넣어 두는 편이 안전하다.

## 검증

```bash
node scripts/check_day.js day31.js
```

개수 규칙, 필드 누락, 퀴즈 정답 범위와 함께 **표기·읽기 정렬**을 앱과 같은 알고리즘으로 확인한다.
정렬에 실패하는 단어는 앱에서 후리가나가 안 붙으므로, 여기서 잡는 것이 훨씬 싸다.

스크립트가 못 잡는 것 — 예문이 자연스러운지, 칼럼이 사실인지 — 은 읽어서 확인한다.

## 앱에 넣기

앱은 Claude 아티팩트로 게시되어 있고, 회차가 앱 파일 안에 박혀 있다(붙여넣기 화면이 없다).

**A. 원고만 전달 (기본값)** — 완성된 객체를 파일로 보내고, 사용자가 `DAYS` 배열 끝에 넣도록 한다.

**B. 아티팩트를 직접 고치기** — 사용자가 요청하면 시도한다. 파일이 7MB를 넘고(음성이 들어 있다)
아티팩트 읽기가 막히는 일이 잦다. 막히면 `references/reading-the-app.md`의 우회 방법을 쓴다.
FDICT 추가가 필요하면 그 작업도 같이 해야 하므로, 직접 고치는 편이 나을 때가 많다.
**고치기 전에 원본을 백업**하고, 되돌릴 방법을 사용자에게 알려 둔다.

## 사용자에 대해

사용자는 본인을 "컴맹"이라고 말한다. 기술 용어를 앞세우지 말고, 무엇을 왜 하는지 짧은 문장으로 설명하고,
파일을 어디에 어떻게 넣는지는 단계별로 안내한다. 결과물은 항상 파일로 만들어 보낸다.
