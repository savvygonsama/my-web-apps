# 스틸링고 회차 데이터 형식

앱 안의 `const DATA = [ ... ]` 배열에 들어가는 객체 하나의 명세다.

## 최상위 필드

```js
{
  no: 21,                              // 회차 번호. 앞 회차 + 1
  title: "大雨[おおあめ]",              // 일본어 제목. 후리가나 표기 포함
  titleKo: "큰 비",                    // 한국어 제목
  story: {...}, words: [...], sentences: [...],
  dialogue: {...}, quiz: [...], column: {...}
}
```

여섯 덩어리가 학습 순서 그대로다. 뉴스를 읽고 → 단어를 익히고 → 예문으로 문법을 보고 →
대화로 써 보고 → 퀴즈로 확인하고 → 칼럼으로 문화를 한 조각 얹는다.

## story — 뉴스 조각

```js
story: {
  topic: "재해·날씨 뉴스",
  lines: [
    { jp: "昨日[きのう]、日本[にほん]の西[にし]の方[ほう]で強[つよ]い《雨[あめ]》が《降[ふ]りました》。",
      ko: "어제 일본 서쪽 지방에서 강한 비가 내렸습니다." },
    // ... 모두 4줄
  ]
}
```

- `lines`는 **4줄**. NHK News Web Easy 한 편을 4문장으로 줄인 분량이다.
- 그날 단어가 나오는 자리는 `《》`로 감싼다. 활용형이어도 감싼다(`《降[ふ]りました》`).
- 이 4줄이 회차의 뼈대다. **story를 먼저 쓰고 거기서 단어 6개를 뽑아라.** 순서를 뒤집으면
  단어가 겉돌고 예문이 억지스러워진다.

## words — 오늘의 단어 6개

```js
words: [
  { jp: "降る", disp: "降[ふ]る", kana: "ふる", mean: "(비·눈이) 내리다",
    note: "하늘에서 무언가 떨어질 때만 씁니다. 「雪[ゆき]が降[ふ]る」(눈이 내리다)도 같은 형태입니다." },
  // ... 모두 6개
]
```

| 필드 | 내용 | 주의 |
|---|---|---|
| `jp` | 사전형 순수 표기 | **대괄호를 넣지 않는다.** `sentences[i].for`와 글자 그대로 같아야 한다 |
| `disp` | 화면에 띄울 후리가나 표기 | `降[ふ]る` |
| `kana` | 읽기 | 가나만 있는 말은 `"―"` |
| `mean` | 한국어 뜻 | 짧게 |
| `note` | 한 문단 설명 | 짝이 되는 말, 헷갈리는 말, 쓰는 자리를 알려 준다 |

`note`가 이 앱의 값어치다. 뜻만 적지 말고 **어떤 말과 붙어 다니는지**를 알려 줘라.
「雨が降る」처럼 짝으로 외우게 하는 것이 낱말 하나를 외우는 것보다 오래 남는다.

## sentences — 단어마다 예문 1개

`words`와 **1:1, 같은 순서**로 6개.

```js
{
  for: "降る",                                   // words[i].jp 와 완전히 같아야 함
  jp: "今日[きょう]は《雨[あめ]》が《降[ふ]ります》。",
  ko: "오늘은 비가 내립니다.",
  frame: "A は  B が  ~ます",                     // 문형 뼈대. 기호와 공백으로 보여 준다
  parts: [
    { p: "今日[きょう]は", r: "きょうは", w: "오늘은",
      why: "「は」는 \"이제부터 이것에 대해 말하겠습니다\"라고 화제를 세우는 표시입니다. 읽을 때는 '와'로 읽습니다." },
    { p: "《雨[あめ]》が", r: "あめが", w: "비가", why: "「が」는 실제로 그 동작을 하는 주인공을 가리킵니다." },
    { p: "《降[ふ]ります》。", r: "ふります", w: "내립니다", why: "동사의 정중형입니다." }
  ],
  why: [
    "초보자가 가장 많이 헷갈리는 것이 <b>は와 が</b>입니다. ...",
    "그래서 「今日<b>が</b>雨が降ります」라고는 말하지 않습니다. ...",
    "날씨는 사람 마음대로 되지 않는 일이라 「が」와 잘 붙습니다. ..."
  ],
  swap: { jp: "明日[あした]は雪[ゆき]が降[ふ]ります。", ko: "내일은 눈이 내립니다." }
}
```

- `parts`의 `p`를 순서대로 이어 붙이면 `jp`와 **한 글자도 다르지 않아야** 한다.
  구두점도 `p` 안에 포함시킨다. 검증 스크립트가 가장 자주 잡아내는 오류다.
- `r`은 그 조각의 가나 읽기, `w`는 한국어 뜻, `why`는 한 문장짜리 이유다.
- `why`(문장 단위, 바깥쪽)는 **3개**. 문법 규칙 하나를 세 각도에서 짚는다:
  규칙 → 그래서 이렇게는 안 쓴다 → 같은 모양의 다른 예.
- `swap`은 같은 문형에 낱말만 바꾼 문장이다. 문형이 재사용된다는 걸 몸으로 알게 하는 장치다.

## dialogue — 짧은 대화 6턴

```js
dialogue: {
  situation: "비가 많이 오는 날, 이웃 사람과 아파트 현관에서 마주쳤습니다.",
  turns: [
    { me: false,                                 // false = 상대, true = 나. 번갈아 나온다
      jp: "おはようございます。今日[きょう]はすごい《雨[あめ]》ですね。",
      ko: "안녕하세요. 오늘은 비가 굉장하네요.",
      tip: "「〜ですね」는 동의를 구하는 맺음입니다. 날씨 이야기로 말문을 여는 것이 일본의 기본입니다.",
      parts: [ { p: "...", r: "...", w: "...", why: "..." } ]   // sentences의 parts와 같은 형식
    },
    // ... 모두 6턴, false로 시작해 true로 끝난다
  ]
}
```

- 그날 배운 단어와 문형이 대화 안에서 다시 나오게 짠다. 예문에서 본 「〜ですから」가
  대화에서 또 나오면 학습자가 "아, 이래서 배웠구나" 하게 된다.
- `tip`은 그 턴에서 눈여겨볼 한 가지. 인사 예절, 맞장구, 생략된 말 같은 것.
- 마지막 턴은 대화를 닫는 인사로 끝낸다.

## quiz — 8문항

```js
quiz: [
  { q: "「雨[あめ]」와 짝을 이루는 동사는?",
    opts: ["降[ふ]る", "止[と]まる", "増[ふ]える"],
    ans: 0,                                      // 0부터 세는 번호
    msg: "비는 「降[ふ]る」와 짝입니다. 「雨[あめ]が降[ふ]ります」로 통째 외우세요." }
  // ... 모두 8문항
]
```

- `opts`는 **항상 3개**. `ans`는 `0`~`2`.
- 그날 다룬 것만 묻는다. 오답 보기도 그날 나온 말에서 고르면 복습이 한 번 더 된다.
- `msg`는 정답 해설. 왜 그런지 한 줄로 짚어 준다.
- **정답 자리를 한쪽에 몰지 않는다.** 처음 20회차는 정답의 67.5%가 첫 보기에 몰려 있었고,
  16~30회차는 앞 네 문항의 정답이 **전부** 첫 보기였다. 그러면 학습자는 낱말이 아니라 자리를 외우고,
  그렇게 얻은 성공은 뒤 네 문항에서 곧바로 배신당한다. 240문항을 다시 흩어 [81, 83, 76]으로 맞춰 두었다.
- **가장 긴 보기가 정답이 되지 않게 한다.** 뜻을 몰라도 큰 덩어리를 누르면 맞는 문항이 된다.
  오답도 같은 길이의 **실제로 쓰이는 표현**으로 채운다.
- **없는 말로 만든 보기는 문항당 하나까지.** 「危[あぶ]いです」처럼 존재하지 않는 말에 후리가나가
  정상적으로 붙으면 진짜 낱말로 보인다. 나머지 오답 하나는 이미 배운 진짜 말로 둔다.
- **질문과 보기에 문법 용어를 쓰지 않는다.** 「정중형으로 바꾸면?」이 아니라 「정중하게 말하면?」이다.
  용어는 해설에서만, 그것도 꼭 필요할 때만 쓴다.
- **활용을 규칙으로 단정하지 않는다.** 「「える」로 끝나는 동사는~」이라고 쓰면 「帰[かえ]る」에서 무너지고,
  앱이 제 본문과 모순된다. 「이 낱말은 이렇게 바뀝니다」 수준으로 낮춘다.
- **기존 문항과 겹치지 않는지 반드시 대조한다.** 정답 문장이 같으면 그것은 새 문항이 아니다.
  같은 회차 안은 물론 다른 회차와도 대조한다.

### 여덟 문항의 짜임

앞 네 문항과 뒤 네 문항이 하는 일이 다르다.

| 자리 | 하는 일 |
|---|---|
| 1~4번 | 그날 배운 것을 그대로 확인한다. 회차가 올라가도 이 넷은 늘 쉽게 유지한다 |
| 5번 | 그날 단어 하나의 뜻. 어느 회차에서나 가장 쉬운 문항이다 |
| 6~8번 | 회차 묶음의 단계에 맞춰 한 걸음씩 깊어진다 (아래) |

1~4번을 쉽게 두는 것이 뒤 네 문항을 올릴 수 있게 해 주는 받침이다. 순서를 바꾸지 않는다.

### 5회차 묶음마다 오르는 단계

앱의 `QUIZ_WAYS`와 같은 순서다. 화면에서는 **5번 문항 바로 앞**에 얇은 구분선과 함께
「여기부터 — 빈칸 채우기」 같은 회색 알약으로 표시된다. 퀴즈 맨 위가 아니라 실제로 깊어지는
그 자리에 표를 세우는 것이고, **「난이도」나 「N단계」라는 말은 화면에 쓰지 않는다.**
있지도 않은 어려움을 예고하면 겁을 주거나 지키지 못할 약속이 된다.

| 회차 | 단계 | 6~8번이 묻는 방식 |
|---|---|---|
| 1~5 | 낱말과 짝 | 뜻, 어울리는 말, 기본 활용 |
| 6~10 | 모양 바꾸기 | 배운 말을 그날 문형에 맞게 바꾸기 |
| 11~15 | 빈칸 채우기 | 문장 속 조사와 어형 고르기 |
| 16~20 | 장면에 맞는 말 | 상황을 주고 알맞은 표현 고르기 |
| 21~25 | 바른 문장 고르기 | 비슷한 문장 셋 중 바른 것 |
| 26~30 | 속뜻 헤아리기 | 뉘앙스와 업무에서의 실제 의미 |

**여기서 올라가는 것은 묻는 방식뿐이다. 새로운 문법 지식을 더하지 않는다.**
이 선을 지켜야 회차를 건너뛴 사람도 그날 본문만 읽으면 풀 수 있다. 이것이 난이도를
올리면서도 초보자를 잃지 않는 유일한 방법이라, 어겼을 때 잃는 것이 가장 크다.

31회차 이후를 새로 쓴다면 마지막 단계(속뜻 헤아리기)를 그대로 이어 간다.

### 심사에서 되풀이해 걸린 것

`references/review-panel.md`의 5인 심사를 돌리면 퀴즈에서 늘 같은 세 가지가 걸린다.
원고를 넘기기 전에 스스로 먼저 확인하면 한 바퀴를 아낀다.

1. **기존 문항의 재탕** — 가장 많이 걸린다. 새로 쓴 것 같아도 앞 네 문항이 이미 물은 것이다.
2. **정답 자리 쏠림과 보기 길이** — 문항을 풀지 않고도 맞힐 수 있으면 확인이 아니다.
3. **해설이 실무와 어긋남** — 사전적 차이를 업무 조언으로 늘여 쓸 때 생긴다.
   「確認[かくにん]します」를 「이미 알고 있다는 뜻」이라 쓴 것이 그 예다.
   실제로는 「社内[しゃない]で確認[かくにん]いたします」가 「알아보고 답하겠다」로 통한다.

## column — 마무리 칼럼

```js
column: {
  word: "お見舞[みま]い", kana: "おみまい", ko: "병문안, 위문",
  title: "재해가 나면 안부를 묻는 것이 아니라 「お見舞[みま]い」를 합니다",
  body: [ "문단 1 ...", "문단 2 ...", "문단 3 ..." ],
  note: "「お見舞[みま]い」에는 반드시 「お」가 붙습니다."
}
```

- 그 회차 주제와 이어지는 **말 한 개**를 골라, 그 말이 일본 사회에서 어떻게 쓰이는지를 이야기한다.
- `body`는 3문단. 마지막 문단은 가능하면 **업무 장면**으로 내린다
  (거래처, 메일, 회의). 사용자가 회사에서 쓸 말을 찾고 있기 때문이다.
- `note`는 형태상 주의 한 줄.

## 음성 키 계산

앱은 문장을 읽어 줄 때 `AUDIO_DATA[key]`를 먼저 찾는다. 키는 이렇게 만든다.

1. 표시용 표기를 **읽기용 텍스트**로 바꾼다: `{표기}[읽기]` → 읽기, `한자[읽기]` → 한자, `《》` → 제거.
2. UTF-8 바이트에 FNV-1a 32비트 해시를 돌린다.
3. 16진수 8자리(앞을 0으로 채움)가 키다.

```js
function keyOf(t) {
  const b = new TextEncoder().encode(t);
  let h = 0x811c9dc5;
  for (const x of b) { h ^= x; h = Math.imul(h, 0x01000193) >>> 0; }
  return h.toString(16).padStart(8, "0");
}
```

키가 없으면 `audio/{key}.mp3` → 그것도 없으면 브라우저 내장 음성으로 물러난다.
**그래서 새 회차를 넣어도 앱은 멈추지 않는다.** 소리는 나되 목소리가 달라질 뿐이다.
