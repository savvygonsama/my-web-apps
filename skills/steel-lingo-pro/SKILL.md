# 스틸링고 Pro 회차 만들기

곤사마(@POSCO)가 만든 일본어 학습 웹앱 중 실무자용. 짝이 되는 입문용 앱 **스틸링고 Lite**와
표기 규칙은 같지만 데이터 형식과 독자가 완전히 다르므로 스킬도 따로 둔다.

| | 내용 |
|---|---|
| 대상 | 일본 거래처와 일하는 실무자 |
| 소재 | 철강 실무 — 가격·계약·납기·클레임 |
| 현재 | 15회차 |
| 명세 | `references/schema-training.md` |
| 검증 | `node scripts/check_day.js --training 파일` |
| 심사 | `references/review-panel.md` — 5인 페르소나, 항목별 9.5점 이상 |
| 참고 | `references/glossary.md`(철강·자동차 조달 용어집), `references/business-japanese.md`(상담·메일 정형표현) |

이 앱은 원래 "철강 일본어 매일 훈련"이라는 이름으로, 팀원 대상 일본어 훈련 스킬로
시작했다. 그 시절에 쌓은 용어집·표현집·심사 방식을 이 스킬이 이어받는다.

## 작업 순서

1. **명세를 읽는다** — `references/schema-training.md`. 여기 요약만 보고 쓰면 반드시 어긋난다.
2. **소재 정하기** — 사용자에게 묻거나 제안한다. 실제 상담에서 벌어지는 장면 하나
   (가격 인상 요청, 납기 지연 사과, 클레임 대응 등). 회차 하나가 장면 하나다.
3. **용어·표현 확인** — 지어내지 말고 `references/glossary.md`, `references/business-japanese.md`를
   먼저 본다. 업계에서 실제로 통용되는 말인지 확인한다. 그럴듯한 조어를 쓰면 학습자가
   고객 앞에서 못 알아듣는 말을 하게 된다 — 이 스킬에서 가장 치명적인 실패다.
4. **원고 쓰기** — 문체와 난이도 기준은 `references/style.md`를 읽고 따른다.
5. **검증** — `scripts/check_day.js --training 파일`을 돌린다. 통과할 때까지 고친다.
6. **심사** — `references/review-panel.md`의 5인 페르소나로 평가한다.
   항목 하나라도 9.5점 미만이면 고치고 다시 본다. 이 단계를 생략하지 않는다.
7. **전달** — 완성된 회차 객체를 `.js` 파일로 저장해 사용자에게 보낸다.

## 표기 규칙

앱이 화면에 그릴 때와 음성으로 읽을 때 쓰는 표기가 세 가지다. 이걸 틀리면 후리가나가 깨진다.

| 쓰는 법 | 화면 | 음성 | 쓰는 곳 |
|---|---|---|---|
| `場所[ばしょ]` | 場所에 ばしょ 후리가나 | 한자 그대로 엔진에 넘김 | 모든 일본어 |
| `{9時}[くじ]` | 9時 (후리가나 없음) | くじ | 숫자·시각·단위·연도 |
| `《雨[あめ]》` | 노란 형광펜 | 표시 없이 읽음 | 그 회차 용어가 문장에 나올 때 |

- 한자 덩어리에만 대괄호를 붙인다. 오쿠리가나는 밖에 둔다 — `降[ふ]る`가 맞고 `降る[ふる]`는 틀리다.
- 히라가나·가타카나만 있는 말에는 대괄호를 붙이지 않는다.
- **숫자와 단위는 반드시 `{}[]`로 읽기를 달아라.** 음성 엔진은 숫자·연도·단위를 자주 엉뚱하게
  읽는다. 특히 아래 조합이 실제로 자주 나온다 — 값을 만들 때마다 대조한다.

  | 표기 | 읽기 |
  |---|---|
  | `{45g/㎡}[よんじゅうごグラムまいへいほうメートル]` | よんじゅうごグラムまいへいほうメートル |
  | `{590MPa級}[ごひゃくきゅうじゅうメガパスカルきゅう]` | ごひゃくきゅうじゅうメガパスカルきゅう |
  | `{2026年度}[にせんにじゅうろくねんど]` | にせんにじゅうろくねんど |
  | `{4四半期}[よんしはんき]` | よんしはんき |
  | `{500トン}[ごひゃくトン]` | ごひゃくトン |

- 한국어 문자열 안에서 인용할 때는 `"..."` 대신 「」를 쓴다.
- 강조는 `<b>...</b>`, 낱말 강조는 `<span class='kw'>...</span>`. 그 외 태그는 쓰지 않는다.

## 검증

원고를 회차 객체 하나만 담은 파일로 저장한 뒤:

```bash
node scripts/check_day.js --training unit16.js
```

문법 오류, 대괄호·《》 짝, 필드 대응, `ch` 결합 일치, 개수 규칙, 퀴즈 정답 범위를 본다.
스크립트가 못 잡는 것 — 업계 용어가 맞는지, 경어가 자연스러운지, 대화가 실전에서 통하는지 —
은 심사 단계에서 잡는다.

## 음성에 대해

VOICEVOX로 미리 만든 음성이 문장별로 박혀 있다. 키는 **읽을 텍스트의 FNV-1a 32비트
해시(16진수 8자리)**다. 새로 쓴 문장에는 그 음성이 없으면 브라우저 내장 음성으로 자동 대체된다.
회차를 추가해도 앱은 깨지지 않고 소리도 난다 — 다만 목소리가 다르고 억양이 덜 자연스럽다.
사용자에게 이 점을 미리 한 줄로 알려라.

## 사실 관계 (특히 중요)

`article`은 **실제 보도**를 학습용으로 다시 쓴 것이다. 기존 회차를 보면
`real: true`, 출처 매체와 제목, 원문 URL, 그리고 "원문 그대로가 아니다"라는 고지가 함께 들어 있다.

사용자는 지어낸 데이터를 아주 싫어한다. 그러니 기사 지문을 만들 때는:

- **실제 보도를 찾아 근거로 삼는다.** 웹 검색으로 확인하고 출처와 URL을 채운다.
- 확인된 보도를 못 찾으면 `real: false`로 두고 **가상 사례임을 지문 안에 밝힌다.**
  회사명·수치를 그럴듯하게 지어내 실제인 것처럼 쓰지 않는다.
- 숫자를 옮길 때는 원 보도의 숫자를 그대로 쓴다. 반올림하거나 각색하지 않는다.

## 앱에 넣기

Claude 아티팩트로 게시되어 있고, 회차가 앱 파일 안에 박혀 있다(붙여넣기 화면이 없다).

**A. 원고만 전달 (기본값)** — 완성된 객체를 파일로 보내고, 사용자가 넣도록 한다.
넣는 자리는 `DATA` 배열의 맨 끝, 마지막 회차 객체 뒤에 쉼표를 찍고 이어 붙이는 것이다.

**B. 아티팩트를 직접 고치기** — 사용자가 요청하면 시도한다. 음성이 통째로 들어 있어
파일이 7MB를 넘는다. 아티팩트 읽기가 환경의 네트워크 정책에 막히는 일이 잦다.
막히면 `references/reading-the-app.md`의 우회 방법을 쓴다.
어느 쪽이든 **고치기 전에 원본을 백업**하고, 사용자에게 되돌릴 방법을 알려 둔다.

## 사용자에 대해

사용자는 본인을 "컴맹"이라고 말한다. 기술 용어를 앞세우지 말고, 무엇을 왜 하는지 짧은 문장으로 설명하고,
파일을 어디에 어떻게 넣는지는 단계별로 안내한다. 결과물은 항상 파일로 만들어 보낸다.
