# 스틸링고 회차 만들기

곤사마(@POSCO)가 만든 일본어 학습 웹앱 **두 개**를 다룬다. 표기 규칙은 같지만 **데이터 형식이 완전히 다르다.**

| | 스틸링고 Lite 📖 | 스틸링고 트레이닝 🏭 |
|---|---|---|
| 대상 | 일본어를 막 시작한 사람 | 일본 거래처와 일하는 실무자 |
| 소재 | NHK News Web Easy 수준 생활 뉴스 | 철강 실무 — 가격·계약·납기·클레임 |
| 현재 | 20회차 | 15회차 |
| 명세 | `references/schema-lite.md` | `references/schema-training.md` |
| 검증 | `node scripts/check_day.js --lite 파일` | `node scripts/check_day.js --training 파일` |

**어느 쪽인지 먼저 확정하라.** 사용자가 그냥 "스틸링고"라고만 하면 물어봐라.
"입문용 Lite인가요, 철강 실무 트레이닝인가요?" 한 줄이면 된다. 잘못 고르면 원고를 통째로 버린다.

## 작업 순서

1. **어느 앱인지 확정** → 해당 명세 파일을 읽는다. 여기 요약만 보고 쓰면 반드시 어긋난다.
2. **소재 정하기** — 사용자에게 묻거나 제안한다. Lite는 뉴스 한 편으로 소화되는 생활 소재,
   트레이닝은 실제 상담에서 벌어지는 장면 하나(가격 인상 요청, 납기 지연 사과, 클레임 대응 등).
3. **원고 쓰기** — 문체와 난이도 기준은 `references/style.md`를 읽고 따른다.
4. **검증** — `scripts/check_day.js`를 돌린다. 통과할 때까지 고친다. 이 단계를 건너뛰지 않는다.
5. **전달** — 완성된 회차 객체를 `.js` 파일로 저장해 사용자에게 보낸다.

## 표기 규칙 (두 앱 공통)

앱이 화면에 그릴 때와 음성으로 읽을 때 쓰는 표기가 세 가지다. 이걸 틀리면 후리가나가 깨진다.

| 쓰는 법 | 화면 | 음성 | 쓰는 곳 |
|---|---|---|---|
| `場所[ばしょ]` | 場所에 ばしょ 후리가나 | 한자 그대로 엔진에 넘김 | 모든 일본어 |
| `{9時}[くじ]` | 9時 (후리가나 없음) | くじ | 숫자·시각·단위·연도 |
| `《雨[あめ]》` | 노란 형광펜 | 표시 없이 읽음 | 그 회차 단어가 문장에 나올 때 |

- 한자 덩어리에만 대괄호를 붙인다. 오쿠리가나는 밖에 둔다 — `降[ふ]る`가 맞고 `降る[ふる]`는 틀리다.
- 히라가나·가타카나만 있는 말에는 대괄호를 붙이지 않는다 — `やむ`, `ください`.
- **숫자와 단위는 반드시 `{}[]`로 읽기를 달아라.** 음성 엔진은 「9時」를 「きゅうじ」로,
  「2026年度」를 엉뚱하게 읽는다. 앱에서 가장 눈에 띄는 종류의 오류다.
- 한국어 문자열 안에서 인용할 때는 `"..."` 대신 「」를 쓴다. 따옴표 이스케이프 사고를 원천 차단한다.
- 강조는 `<b>...</b>`, 낱말 강조는 `<span class='kw'>...</span>`. 그 외 태그는 쓰지 않는다.

## 검증

원고를 회차 객체 하나만 담은 파일로 저장한 뒤:

```bash
node scripts/check_day.js --lite day21.js
node scripts/check_day.js --training unit16.js
```

문법 오류, 대괄호·《》 짝, 필드 대응, `parts`/`ch` 결합 일치, 개수 규칙, 퀴즈 정답 범위를 본다.
사람 눈으로는 잘 안 잡히는 것들이라, 통과할 때까지 돌리는 편이 훨씬 빠르다.
스크립트가 못 잡는 것 — 번역이 맞는지, 설명이 초보자에게 통하는지 — 은 직접 읽어서 확인한다.

## 음성에 대해

두 앱 모두 VOICEVOX로 미리 만든 음성이 문장별로 박혀 있다.
키는 **읽을 텍스트의 FNV-1a 32비트 해시(16진수 8자리)**다(계산법은 `references/schema-lite.md`).

새로 쓴 문장에는 그 음성이 없다. 이때 앱은 **브라우저 내장 음성으로 자동 대체한다.**
그러니 회차를 추가해도 앱은 깨지지 않고 소리도 난다 — 다만 목소리가 다르고 억양이 덜 자연스럽다.
사용자에게 이 점을 미리 한 줄로 알려라.

## 사실 관계 (트레이닝에서 특히 중요)

트레이닝의 `article`은 **실제 보도**를 학습용으로 다시 쓴 것이다. 기존 회차를 보면
`real: true`, 출처 매체와 제목, 원문 URL, 그리고 "원문 그대로가 아니다"라는 고지가 함께 들어 있다.

사용자는 지어낸 데이터를 아주 싫어한다. 그러니 기사 지문을 만들 때는:

- **실제 보도를 찾아 근거로 삼는다.** 웹 검색으로 확인하고 출처와 URL을 채운다.
- 확인된 보도를 못 찾으면 `real: false`로 두고 **가상 사례임을 지문 안에 밝힌다.**
  회사명·수치를 그럴듯하게 지어내 실제인 것처럼 쓰지 않는다.
- 숫자를 옮길 때는 원 보도의 숫자를 그대로 쓴다. 반올림하거나 각색하지 않는다.

## 앱에 넣기

두 앱 모두 Claude 아티팩트로 게시되어 있고, 회차가 앱 파일 안에 박혀 있다(붙여넣기 화면이 없다).

**A. 원고만 전달 (기본값)** — 완성된 객체를 파일로 보내고, 사용자가 넣도록 한다.
넣는 자리는 `DATA` 배열의 맨 끝, 마지막 회차 객체 뒤에 쉼표를 찍고 이어 붙이는 것이다.

**B. 아티팩트를 직접 고치기** — 사용자가 요청하면 시도한다. 다만 두 앱 모두 음성이 통째로 들어 있어
파일이 7MB를 넘는다. 아티팩트 읽기가 환경의 네트워크 정책에 막히는 일이 잦다.
막히면 `references/reading-the-app.md`의 우회 방법을 쓴다.
어느 쪽이든 **고치기 전에 원본을 백업**하고, 사용자에게 되돌릴 방법을 알려 둔다.

## 사용자에 대해

사용자는 본인을 "컴맹"이라고 말한다. 기술 용어를 앞세우지 말고, 무엇을 왜 하는지 짧은 문장으로 설명하고,
파일을 어디에 어떻게 넣는지는 단계별로 안내한다. 결과물은 항상 파일로 만들어 보낸다.
