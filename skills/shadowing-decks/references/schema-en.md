# ROUNDTABLE — 영어 쉐도잉 회차 형식

앱의 "새 회화 추가" 화면에 붙여넣는 JSON 배열 하나의 명세다.
아래 예시는 실제 1일차(When Money Stops Being Cheap)에서 가져왔다.

## 학습자와 목표 (앱에 적힌 기준 그대로)

- 한국인 직장인, 토익스피킹 6~7급. 목표는 **정확한 표현과 자연스러운 구어체**.
- 형식은 **토론**이다. 두 사람이 한 주제를 놓고 서로 다른 자리에서 이야기한다.
  茶馆이 관계 속의 대화라면, 이쪽은 회의실의 대화다.

## 반드시 지킬 조건

- 두 사람(A/B)이 한 주제로 토론, **20줄**, A/B 번갈아, 한 줄 **10~18단어**.
- **지어낸 통계·날짜·인용 금지.** 속보성 뉴스 대신 **오래 유효한 구조와 메커니즘**을 다룬다.
  (금리가 자본비용을 통해 투자 결정에 미치는 경로 같은 것. "지난달 발표된 수치" 같은 것이 아니라.)
- 관용어·구동사·구어체·연어를 문장마다 자연스럽게 섞고, `notes`로 설명한다.
- `tip`에는 **한국인이 흔히 틀리는 지점**이나 함께 외울 확장 표현을 적는다.

---

## 전체 모양

```json
[{
  "id": "w2d1", "day": 8, "cat": "주제분류", "level": "B2",
  "title": "영어 제목", "titleKo": "한국어 제목 — 부제",
  "names": { "A": "Nora (재무)", "B": "Sam (영업·운영)" },
  "brief": ["배경설명 1", "2", "3", "4"],
  "lines": [ … 20줄 … ],
  "keys": [ … 핵심 표현 … ],
  "out":  [ … 말하기 과제 … ]
}]
```

`id`는 `w` + 묶음번호 + `d` + 일차. `cat`은 주제 분류 — 경제 / 기술 / 조직 / 사회 등.
중국어판과 달리 **`titlePy`와 `vocab`이 없다.** 병음도 끊어읽기도 없다.

`names`는 **역할이 서로 다르게** 잡는다. 재무와 영업, 엔지니어와 PM처럼
입장이 갈려야 토론이 굴러간다. 둘 다 같은 편이면 대화가 아니라 설명문이 된다.

`brief` 4문단은 **주제의 메커니즘**을 설명한다. 1일차가 좋은 본보기다 —
자본비용이 무엇인지, 왜 충격이 시차를 두고 오는지, 실무에서 쓰는 개념(hurdle rate, payback period)이
무엇인지, 그리고 그것이 현장에서 어떻게 나타나는지. 용어 나열이 아니라 **인과의 사슬**로 쓴다.

## lines — 대화 20줄

```json
{
  "s": "B",
  "en": "Fair enough, but we've been living with higher rates for a while now. Why is it biting only now?",
  "ko": "일리는 있어요. 그런데 고금리는 한참 겪어 왔잖아요. 왜 하필 지금 타격이 오죠?",
  "notes": [
    { "t": "Fair enough, but ~", "k": "idiom", "m": "그 말도 일리는 있는데, 다만 ~",
      "tip": "상대 말을 인정하고 반박으로 넘어가는 가장 자연스러운 다리입니다. 토론 필수 표현." },
    { "t": "bite", "k": "idiom", "m": "(정책·비용이) 실제로 아프게 작용하다",
      "tip": "When do the sanctions start to bite? 처럼 씁니다." }
  ]
}
```

- `notes`의 `k`는 반드시 이 중 하나:
  `idiom` · `colloquial` · `phrasal` · `collocation` · `business` · `grammar`
- 한 줄에 1~3개. 새 표현이 나온 줄에는 반드시 붙인다.
- `tip`이 이 앱의 핵심이다. 두 방향으로 쓴다.
  - **한국인이 틀리는 지점** — "회의에서 반대할 때 흔히 쓰는 'I don't agree'를 push back on으로 바꾸면 톤이 좋아집니다."
  - **함께 외울 확장** — "solid numbers / solid evidence / solid track record 로 자주 붙습니다."
- 발음이 뭉개지는 덩어리는 그것도 적어 준다. "of를 거의 /əv/로 흘립니다. 붙여서 한 덩어리로 연습하세요."

### 대화를 굴리는 법

토론이므로 **주고받는 구조**가 있어야 한다. 1일차의 흐름이 본보기다.

```
A 상황 제시 → B 의문 제기 → A 원인 설명 → B 반박("Fair enough, but…")
→ A 메커니즘 해명 → B 실무적 함의 → … → 합의 또는 남은 쟁점
```

한 사람이 계속 설명하고 다른 사람이 맞장구만 치면 안 된다. **B가 반박할 자리를 만들어라.**
그 반박 문장들이 학습자가 실제로 회의에서 쓸 말이다.

---

## keys — 핵심 표현

```json
{ "en": "the sticking point", "ko": "합의를 막는 결정적 걸림돌",
  "ex": "The sticking point is the delivery schedule, not the price." }
```

- 6~8개. 중국어판과 달리 `en` / `ko` / `ex` 세 칸만 쓴다.
- `ex`는 대화에 나온 문장이 아니라 **다른 상황으로 옮긴 문장**으로.

---

## out — 말하기 과제

```json
{ "q": "Why do rate hikes take time to affect corporate investment?",
  "hint": "cost of capital / roll over / with a lag" }
```

- 3개. **질문은 영어로** 쓴다(중국어판은 한국어 질문이라 다르다).
- `hint`에는 답에 써야 할 표현을 `/`로 나열한다.
- 단순 암기가 아니라 **배운 표현으로 설명하게** 만드는 질문으로.
