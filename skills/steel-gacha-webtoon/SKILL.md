# 스틸가챠s 웹툰 제작

앱 `savvygonsama/steel-grade-gacha`의 강종 캐릭터로 만드는 세로 스크롤 일상 개그 웹툰.
**Claude는 기획·콘티·프롬프트·앱 반영을 맡고, 그림은 사용자가 ChatGPT 이미지 생성으로 뽑는다.**
앱에서는 첫 화면 보라색 「스틸가챠s」 버튼 → 에피소드 목록 팝업 → 세로 뷰어로 본다.

| 참조 | 내용 |
|---|---|
| `references/style-lock.md` | **화풍이 화마다 바뀌는 문제의 원인과 고정 방법**, 화풍 기준판(스타일 앵커) 만들기 |
| `references/prompt-template.md` | ChatGPT용 시작 메시지 [0]·장면 프롬프트 틀·다시 그리기 문장 (매 화 이걸로 쓴다) |
| `references/app-publish.md` | 받은 그림을 앱에 올리는 절차와 `scripts/add_episode.py` 사용법 |
| `references/episodes.md` | 연재 기록(제목·컷 수·펀치), 안 쓴 후보, **사용자 피드백 기록** |
| `references/characters.md` | 캐릭터 바이블: 개그 역할, 말투, 그림 키, 조연 규칙 |
| `references/steel-facts.md` | 철강·앱 사실 함정과 정정 목록 |
| `references/art-prompts.md` | 캐릭터 시트 프롬프트(새 조연 시트 만들 때), 팔레트 |
| `references/review-panel.md` | 5인 패널 검토 기준(사용자가 "멀티페르소나 검토"를 요청할 때만) |

## 한 화를 만드는 순서

1. **아이디어 후보** — 사용자가 "N화 아이디어/후보"를 청하면 5~15개를 낸다. 각 후보: 제목, 출연, 컷 수, 흐름 4~8줄, 마지막 컷, 아는 사람 포인트. 끝에 추천 2~3개와 이유. 고르기 전에 콘티·프롬프트를 쓰지 않는다.
2. **콘티 표** — 고른 후보를 `| 컷 | 그림 | 말풍선 |` 표로 쓴다. 앱 각주 한 줄을 함께 적는다.
3. **ChatGPT 프롬프트** — `references/prompt-template.md` 틀대로 [0] 시작 메시지 + 장면별 메시지 + 다시 그리기·빈 말풍선 문장. 화풍 고정 규칙(`style-lock.md`)을 반드시 따른다.
4. **검수** — 사용자가 그림을 보내면 순서·대사·캐릭터 혼동·화풍 차이를 확인하고, 문제 컷만 다시 그리는 문장을 준다. 이해가 어렵다는 반응이 오면 그림 탓보다 **이야기 연결(동기·원인과 결과)** 을 먼저 의심한다.
5. **앱 반영** — `references/app-publish.md` 절차로 올리고 PR을 만든다. 머지는 사용자가 한다.
6. **기록** — `references/episodes.md`에 화 정보와 새로 받은 피드백을 적는다.

## 이야기 규칙

### 독자와 톤
- 주 독자는 **철강 업계 직장인 + 앱 사용자**. 목표 반응은 **피식 + 흐뭇**. 철강을 몰라도 웃겨야 하고, 알면 한 번 더 웃게.
- 현업 공감 소재가 잘 먹힌다(톤당 환산, 회식, 클레임, 감사, 월말, 샘플 요청). 결말이 '더 팔자'·'우리 소재가 대단하다'로 가면 흐뭇함이 산다.

### 구조
- 세로 스크롤, **한 컷 = 한 장(2:3 세로)**. 기본 6~8컷, 사용자가 원하면 9컷까지.
- 상황 → 전개 → 기대 쌓기 → **마지막 컷 뒤집기**. 펀치를 앞 컷에서 말로 예고하지 않는다.
- 마지막 컷은 **대사 없는 그림 반전**이 가장 잘 먹혔다(2화 제외 전부). 사용자가 '확대 컷은 맨 마지막'처럼 순서를 정하면 그대로 따른다.
- 펀치에 쓰는 소품은 앞 컷에 미리 심는다.

### 이해하기 쉽게 (사용자 피드백에서 나온 규칙)
- **새 캐릭터는 한 화에 한 명**, 이미 나온 셋(포오·씨알·도금이) 사이에 들어오는 구도. 첫 등장 컷에 이름표 "이름 · 소재".
- 독자가 아직 모르는 캐릭터의 지식을 전제로 한 이야기는 쓰지 않는다(「사무실 사촌들」 실패).
- 캐릭터가 무언가를 하면 **왜 하는지 한 줄**이 있어야 한다. 대사를 바꿀 때 동기가 빠지지 않는지 다시 본다.
- **원인과 결과가 그림에 보여야 한다**(무너진 서류 더미, 떨어지는 문짝처럼).

### 소재 존중
- 어떤 강종도 손님·열등·불청객으로 그리지 않는다. 새 캐릭터 화는 **그 소재만의 매력을 뽐내고 다들 감탄하는** 방향으로(4화 「볼트 하나」: 볼트를 빼자 차가 무너짐 → 선재 없인 차가 안 됨).

### 컷 정보량
- 컷당 인물 **2명 이하**가 원칙. 줄다리기·단체 사진 같은 장면만 예외(화당 1~2장).
- 컷에 행동 하나, 말풍선 **2개 이하**, 한 줄 **25자 안팎**.

### 말투 (대사만 봐도 누군지 알게)
- 포오: 짧은 반말, **느낌표 없음**, 덤덤한 한마디.
- 씨알: 단정형 반말 + 느낌표, **숫자·기준**을 붙인다.
- 도금이: 느긋한 반말 + 물결표, **'~잖아'는 도금이 전용**.
- 이지: 주연 중 유일한 **해요체**, 웃으며 선을 긋는다.
- 타래: 해맑은 반말, 매 줄 **물음표**. **"~해도 돼?" 하고 묻고 대답 전에 이미 하고 있다.** '뾰잉'은 쓰지 않는다(사용자가 싫어함).
- 모든 캐릭터는 **성별 없음**. 형·오빠·삼촌 같은 성별 호칭 금지, 영어 프롬프트에서도 he/she 대신 이름.

### 사실
- 철강 사실 오류 금지(`references/steel-facts.md`). 숫자는 계산 근거를 콘티 아래 적는다(2화: 냉연 톤당 약 100만 원, 삼겹살 kg 9만 원 → 90배).
- 실존 회사·브랜드·사고·외모·나이·성별 소재 금지. 다치는 장면 금지.
- 앱 각주는 그림 밖 한 줄, 약어 없이.

## 그림 도구
- **ChatGPT 하나로 고정한다.** 2화만 Gemini로 그렸다가 선 굵기·채도가 크게 달라졌다. 다른 도구를 쓰자고 하면 화풍 차이를 먼저 알린다.
- 한 화 = 한 채팅. 매 화 **같은 화풍 기준판 + 캐릭터 시트**를 첨부한다(직전 화 그림을 기준으로 쓰지 않는다). 자세한 것은 `style-lock.md`.
